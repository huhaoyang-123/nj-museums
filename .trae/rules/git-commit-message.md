## Git 提交信息规范

### 格式结构
```
<类型>(<范围>): <简短描述>

<详细描述（可选）>

<关联信息（可选）>
```

### 类型说明
| 类型         | 含义     | 适用场景                       |
| ------------ | -------- | ------------------------------ |
| **feat**     | 新功能   | 新增功能、页面、API、组件      |
| **fix**      | 修复Bug  | 修复代码缺陷、修复接口问题     |
| **docs**     | 文档更新 | 更新README、注释、文档         |
| **style**    | 代码风格 | 格式化、空格、缩进、不影响逻辑 |
| **refactor** | 代码重构 | 重构代码、优化结构、不改变功能 |
| **test**     | 测试相关 | 添加测试用例、完善测试         |
| **chore**    | 杂项任务 | 配置文件、依赖更新、构建脚本   |
| **perf**     | 性能优化 | 提升性能、减少响应时间         |
| **revert**   | 回滚操作 | 撤销之前的提交                 |

### 提交示例

**示例 1：新增功能**
```
feat(api): 添加博物馆AI对话接口

- 接入SiliconFlow AI服务
- 添加/api/ask接口
- 支持POST请求，返回JSON格式回答
```

**示例 2：修复Bug**
```
fix(ui): 修复地图加载失败问题

修复高德地图Key未正确配置导致的加载失败
```

**示例 3：文档更新**
```
docs(readme): 更新项目说明文档

- 添加快速开始指南
- 补充API接口说明
```

**示例 4：代码重构**
```
refactor(service): 重构博物馆数据服务

- 优化数据读取逻辑
- 增加错误处理
- 提高代码可读性
```

### 编写原则
1. **标题不超过50字符**，简洁明了
2. **使用祈使句**，如"添加"、"修复"、"更新"
3. **范围清晰**，说明修改的模块或文件
4. **详细描述**用于说明改动的原因和内容
5. **英文用小写**，中文用中文标点

### 关联信息格式
```
Closes #123          // 关闭issue #123
Related to #456      // 关联issue #456
```
